Target formats (FHIR)

FHIR inputs accepted as the target side of a comparison:

FormatExtensionNotes
Single FHIR document (Bundle or standalone resource, e.g. Observation) .json One JSON object per file. A Bundle's entry[].resource array is unpacked into Patient/Encounter/Observation/etc. groups per domain.
NDJSON (newline-delimited FHIR resources).ndjson, .ndjsonl One resource per line, no enclosing Bundle wrapper required — the format used by FHIR Bulk Data Export and many EHR/warehouse batch exports. See NDJSON ingestion.

Best-effort FHIR R4B structural validation (via the fhir.resources library) runs automatically and is surfaced as non-blocking warnings — it never rejects a target file outright, since reconciliation should still run against whatever a real target system actually emitted.
