Konkord — Healthcare Data Assurance

Konkord is a pure Python library and CLI that reconciles a source HL7v2 message against a target FHIR R4B resource or Bundle, field by field, and tells you exactly what matches, what's missing, and what drifted — no server, no container, no REST API to run.

Overview

What Konkord does

A stateless, synchronous, in-process reconciliation engine with an optional persistence layer for job history — not a FHIR validator, not a record-linkage engine, no server to run.

🔍

Field-level reconciliation

Compares concept code, value, unit, interpretation, reference range, status, and timestamps between source and target.

🧠

Multi-domain rule packs

20 domains — labs, identity, encounters, medications, allergies, conditions, procedures, coverage, prior authorization, claims, immunizations, documents, goals, care teams, diagnostic reports, risk adjustment, CDex, terminology, and migration drift — each with its own rule pack.

🔑

Exact-key matching

Matches by explicit domain key (LOINC code, RxNorm-style ingredient code, resource id) — no fuzzy/probabilistic linkage.

📈

Drift & trend detection

With correlation_id + the optional db extra, detects sync gaps, contract drift, population shifts, and overwritten late updates across repeated runs.

📥

CLI or library

Run the bundled konkord CLI (compare, jobs, status) against files, or call konkord.engine/konkord.reconciliation functions directly from a script or notebook.

📋

Evidence-grade reports

Every run returns a structured, serializable report: one PASS/WARN/FAIL/INDETERMINATE finding per check, plus an overall status.
